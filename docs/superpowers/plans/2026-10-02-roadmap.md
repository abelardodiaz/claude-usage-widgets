# claude-usage-widgets — Roadmap (oleadas → fases → tareas)

> **Para agentes:** este documento es el mapa. Cada oleada tiene su plan detallado propio
> (`YYYY-MM-DD-wN-*.md`), escrito al **iniciar** esa oleada con lo aprendido en la anterior.
> Solo se ejecuta desde un plan detallado, nunca desde este mapa.

**Spec:** `docs/superpowers/specs/2026-10-02-claude-usage-widgets-design.md`

## Convenciones

**Dueños.** `PC` = sesión orquestadora de Claude Code en la computadora (escribe planes, revisa y
mergea PRs, escritorio). `TEL` = sesión de Claude Code en el teléfono Android (compila, instala y
prueba Android en el dispositivo).

**Ramas.** Una rama por fase: `wN/fM-slug` (ej. `w1/f2-bandeja`). Las fases de `TEL` usan
`android/wN-fM-slug`. Todo entra a `main` por PR; `main` protegida (sin push directo, CI verde).

**Commits.** Convencionales en español: `feat:`, `fix:`, `docs:`, `test:`, `ci:`, `chore:`.

**Cierre de fase (obligatorio).**
1. CI verde en el PR.
2. **Revisión Fable** con la plantilla de `docs/superpowers/plans/revision-fable.md`.
3. Hallazgos *críticos* e *importantes* corregidos en la misma rama; los *menores* pueden ir a un issue.
4. Merge a `main` y casilla marcada aquí.

**Memos PC ↔ TEL.** En `docs/incoming/` de cada clon (fuera de git). Nombre:
`NNN-YYYYMMDDHHMMSS-from-claude-X-to-claude-Y-tema.md`. Al incorporarse, se mueven a
`docs/procesados/`. El código **nunca** viaja por memo, solo por GitHub.

## W0 — Cimientos (plan: `2026-10-02-w0-cimientos.md`)

- [ ] **F1 Repo base** (PC) — SECURITY.md, CLAUDE.md, plantilla de revisión Fable, Dependabot, CI de contrato, protección de `main`
- [ ] **F2 Contrato** (PC) — `spec/usage-model.schema.json`, `spec/rules.md`, fixtures de parseo/historial/proyección con valores calculados a mano, validador en CI
- [ ] **F3 Spike A1: endpoint de claude.ai** (PC, con Chrome) — descubrir URL, forma y autenticación del uso en claude.ai; guardar fixture anonimizada
- [ ] **F4 Puesto TEL** (PC + usuario) — clon en el teléfono, CLAUDE.local.md con el rol, canal de memos verificado en ambos sentidos, el usuario abre Claude Code allá
- [ ] **F5 Spike A2 + B** (TEL) — mini APK en Java: login WebView en claude.ai → lee cookie → consulta el endpoint de F3; y un AppWidget "hola". Construido e instalado en el teléfono
- [ ] **F6 Cierre W0** (PC) — go/no-go de Android, ajustes a la spec si hicieron falta, plan detallado de W1

## W1 — Windows (Tauri 2)

- [ ] **F1 Esqueleto Tauri** — `desktop/` con Tauri 2, ventana sin marco siempre encima, CSP estricta, CI `cargo test` + `clippy` en Windows/Ubuntu
- [ ] **F2 Núcleo Rust** — `model`, `parse` (pasa fixtures de parseo), `history` y `projection` (pasan fixtures), almacenamiento local de muestras (JSONL, 15 días)
- [ ] **F3 Fuente ClaudeCodeSource** — lectura de `~/.claude/.credentials.json`, sin refresco, manejo 401/429/5xx con backoff, nunca loguear el token
- [ ] **F4 UI** — portar la UI del prototipo a `desktop/ui/`, comando Tauri `get_usage` que solo expone el modelo normalizado, i18n es/en
- [ ] **F5 Bandeja y ventana** — tray (mostrar/ocultar/actualizar/salir), `window-state`, `single-instance`, `autostart` opcional
- [ ] **F6 Release Windows** — workflow de release por tag (`.msi`/`.exe`), checksums SHA-256, firma del updater, prueba manual guiada en Windows 11; se borra `prototype/`

## W2 — Linux (+ Mac best effort) y respaldo claude.ai en escritorio

- [ ] **F1 Build Linux** — AppImage + deb en CI, prueba en Ubuntu (tray en GNOME requiere AppIndicator: documentar)
- [ ] **F2 Credenciales por plataforma** — Keychain en macOS para el token de Claude Code, `.dmg` sin firma
- [ ] **F3 ClaudeAiSessionSource en escritorio** — ventana de login a claude.ai, cookie al almacén del sistema (`keyring`), cerrar sesión borra todo
- [ ] **F4 Release W2** — release multiplataforma, README de instalación por plataforma

## W3 — Android widget (TEL)

- [ ] **F1 core Java** — `android/core/` en Java puro: modelo, parseo (fixture de F3/W0), historial, proyección; pasa los fixtures en JVM (CI Ubuntu + teléfono)
- [ ] **F2 Build** — `android/build.sh` (aapt2 + javac + d8 + apksigner) idéntico en Termux y Ubuntu; job de CI que construye el APK
- [ ] **F3 Login y almacén** — Activity WebView, cookie cifrada con AES-GCM del Android Keystore, cerrar sesión, `allowBackup=false`
- [ ] **F4 Widget** — `AppWidgetProvider` 4×1 y 4×2, JobScheduler cada 15 min, tocar = actualizar
- [ ] **F5 Pruebas en dispositivo** — recorrido automatizado: login, widget, sin red, sesión vencida, rotación, reinicio del teléfono
- [ ] **F6 Release APK** — firma con llave de release en secret de GitHub, APK en Releases, guía de Obtainium

## W4 — Android burbuja (TEL)

- [ ] **F1 Permiso de superposición** — pantalla que explica y lleva al ajuste del sistema
- [ ] **F2 Servicio + burbuja** — foreground service `specialUse`, círculo con % de sesión y color, arrastrable, se pega al borde
- [ ] **F3 Panel expandido** — al tocar: las 3 barras + proyección; sondeo cada 2 min solo visible
- [ ] **F4 Pruebas y release** — batería (sin sondeo con pantalla apagada), recorrido automatizado, release
